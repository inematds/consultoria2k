🪜 Escolher o nível da pirâmide para cada caso

A pirâmide de soluções aplicada ao caso concreto: quando determinístico basta, quando IA num passo é o caminho, quando agente se justifica — e por que registrar a decisão.

Toda recomendação de IA começa com uma pergunta: qual é o nível mais baixo da pirâmide que resolve esse problema? Subir desnecessariamente é o principal motivo de projetos caros que entregam menos que o esperado.

Pirâmide de soluções amber — o andar mais baixo que resolve é sempre a melhor resposta.

1

🧱 Quando determinístico basta

A maioria dos casos de uso que chegam como "projeto de IA" se resolvem na base: com regras, automações, integrações ou um SaaS melhor. Isso não é fraqueza — é a recomendação mais valiosa.

✅ Sinais de que determinístico basta

  • •As regras são claras, explícitas e não mudam com frequência
  • •O problema exige 100% de acerto (ou acerto verificável e auditável)
  • •O volume é baixo e a frequência não justifica automação sofisticada
  • •Não há dados históricos suficientes para treinar ou validar IA
  • •Um SaaS existente já resolve o problema a custo menor

Exemplos na base

  • • Triagem de e-mails por remetente e palavras-chave
  • • Cálculo de desconto por faixa de volume
  • • Roteamento de tickets por categoria fixa
  • • Geração de relatório mensal com template

Quando IA "substituiu" determinístico — e errou

  • • Classificar categorias fixas com LLM (regra faz igual, a R$0)
  • • Gerar relatório com LLM (template resolve igual)
  • • "Entender" formulário estruturado (parse de JSON já resolve)
2

🤖 Quando o caso pede IA num passo

O meio da pirâmide é onde IA agrega de verdade: linguagem natural, imagens, previsões probabilísticas, ambiguidade. O fluxo continua determinístico antes e depois — IA entra cirurgicamente onde regra não resolve.

📐 O padrão wrapper determinístico

// Entrada estruturada
recebe_texto_do_cliente()
↓ determinístico: limpa, normaliza, valida
chama_ia(texto_limpo) // ← único passo com IA
↓ IA: classifica intenção
valida_saída_da_ia(resultado)
↓ determinístico: roteia, registra, notifica
entrega_resultado_ao_sistema()
✓ Ideal para IA num passo
  • • Classificar intenção em texto livre
  • • Extrair entidades de documentos
  • • Resumir longos textos
  • • Detectar sentimento em avaliações
  • • Prever churn com features numéricas
Vantagens do padrão
  • • Fluxo testável end-to-end
  • • Módulo de IA substituível
  • • Fallback para humano bem definido
  • • Custo de API controlado
  • • Auditável: sabe onde o erro aconteceu
3

🛰️ Quando justifica um agente

Agentes são indicados para casos que exigem múltiplas decisões autônomas encadeadas com ferramentas. São raros na consultoria típica — e devem ser.

Critérios para justificar agente

  • ✓Múltiplas decisões sequenciais impossíveis de pré-definir
  • ✓Ferramentas (APIs, código, buscas) necessárias para resolver
  • ✓O custo do erro por ação é tolerável e reversível
  • ✓Supervisão humana disponível para revisar

Sinais de que agente é excesso

  • ✗O fluxo tem passos bem definidos (workflow resolve)
  • ✗O erro tem custo alto ou é irreversível
  • ✗A equipe não tem capacidade de supervisionar
  • ✗A principal justificativa é "parece mais avançado"

💡 Dica prática

Na maioria dos projetos de consultoria, o máximo necessário é IA num passo. Se alguém sugerir agente, pergunte: "O que acontece quando o agente tomar uma decisão errada?" Se não houver resposta satisfatória, a resposta é workflow com IA.

4

📐 Custo × risco × tempo por nível

Cada andar da pirâmide tem um perfil distinto de custo, risco e tempo. Apresentar esse comparativo ao cliente — com estimativas reais — é parte do business case.

Nível Custo build Custo operação Risco Tempo médio
🧱 Determinístico $ $ (quase zero) Baixo 1–4 sem
🤖 IA num passo $$$ $$ (API + monitor) Médio 4–12 sem
🛰️ Agente $$$$$ $$$$ (API + supervisão) Alto 12–24 sem

📊 Como usar a tabela com o cliente

Apresente as três opções lado a lado com números reais do contexto do cliente. Deixe que ele veja a diferença. Na maioria dos casos, o andar mais baixo que resolve o problema será escolhido — sem precisar argumentar.

5

🧪 Híbrido: determinístico com IA cirúrgica

O padrão mais maduro e recomendável para produção: manter a lógica de negócio em código determinístico e usar IA apenas no ponto onde regra não resolve — como módulo substituível, com fallback explícito.

⚙️ Por que o híbrido é mais robusto

Testabilidade

O fluxo determinístico é testável com testes unitários. O módulo de IA é testável separadamente com um conjunto de casos.

Substituibilidade

Se um modelo melhor aparecer, só o módulo de IA muda — o restante do sistema fica intacto.

Fallback

Se a IA estiver indisponível, o fluxo pode continuar com regra ou escalada para humano — sem parar tudo.

Auditabilidade

Sabe exatamente onde a IA foi chamada, com qual entrada e com qual saída. Fundamental para compliance.

6

✅ Decidir o nível e registrar o porquê

A decisão de qual nível usar deve ser explícita e documentada. Não precisa ser longa — três perguntas bastam. O registro protege o consultor, alinha o time e permite revisão inteligente quando o contexto muda.

📝 Template de registro de decisão

Caso de uso: Triagem de e-mails de suporte
Nível escolhido: IA num passo (classificação de intenção)
Por que não determinístico: vocabulário do cliente é variável demais para regras fixas cobrirem bem
Por que não agente: o roteamento após a classificação é determinístico e bem definido
Critério para revisar: se acurácia cair abaixo de 85% ou custo de API superar R$500/mês

💡 Dica prática

Trate o registro de decisão como parte do entregável do projeto — não como burocracia. Ele é o que transforma um projeto de consultoria num ativo de conhecimento para o cliente e para você.

🎒 Resumo do módulo

✓

✓

✓

✓
